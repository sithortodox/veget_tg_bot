# «ОВОЩНОЙ» — Telegram-бот локального маркетплейса овощей и фруктов

Реализация по ТЗ v3.0. Покупатель отправляет список продуктов свободным текстом,
бот находит ближайшие магазины, продавец подтверждает наличие, формируется
предзаказ, затем самовывоз или пешая доставка. Только постоплата при получении.

## Стек

- Python 3.11+, aiogram 3.x
- PostgreSQL + PostGIS (схема в `sql/init.sql`)
- Redis (FSM)
- OpenAI API (парсинг списка, опционально) + regex-fallback
- rapidfuzz (матчинг товаров), APScheduler (таймауты и предзаказы)
- DaData + Nominatim (геокодирование)

## Быстрый старт

```bash
# 1. Поднять инфраструктуру
docker compose up -d

# 2. Окружение
cp .env.example .env
# заполнить BOT_TOKEN, ADMIN_TELEGRAM_IDS, при желании OPENAI_API_KEY и DADATA_TOKEN

# 3. Зависимости
python3.11 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 4. Запуск
python -m app.main
```

Схема БД накатывается автоматически из `sql/init.sql` при старте docker-контейнера `db`.
Дополнительно `main.py` выполняет `create_all` для разработки (идемпотентно).

## Структура

```
app/
├── main.py           # точка входа: бот, диспетчер, сервисы, плагины, планировщик
├── config.py         # все настройки и таймауты из .env
├── constants.py      # статусы, роли, события
├── db/               # SQLAlchemy-модели и сессии
├── services/         # бизнес-логика (парсер, матчер, гео, заказы, баны, предзаказы…)
├── handlers/         # роутеры aiogram по ролям
├── keyboards/        # reply/inline клавиатуры
├── states/           # FSM-группы состояний
├── middlewares/      # сессия БД, загрузка пользователя, проверка бана
├── plugins/          # точка расширения без правки ядра
└── utils/            # форматирование, время
```

## Как расширять проект

1. **Новый сервис** — модуль в `app/services/`, регистрация в `setup_services()`
   (`app/services/__init__.py`) через `ServiceRegistry`. Хендлеры получают сервис
   из `data["services"]`.
2. **Новый обработчик** — модуль в `app/handlers/` с экспортом `router`;
   подхватывается автоматически в `app/handlers/__init__.py` (или добавьте
   вручную в список `CORE_MODULES`).
3. **Плагин** — модуль в `app/plugins/` с функцией `register(ctx)`.
   Перечислите имя модуля в `PLUGINS` в `app/plugins/__init__.py`.
   Плагину доступны bot, dp, services, config — ядро не правится.
4. **Провайдер LLM/геокодера** — реализуйте протокол в `parser.py`/`geo.py`
   и подключите в конфиге; fallback-цепочка описана в докстрингах.

## Роли и сценарии

- Покупатель: `/start` → «Я покупатель» → регистрация → текстовый список → предзаказ → самовывоз/доставка → постоплата.
- Продавец: регистрация магазина → витрина → подтверждение позиций → сборка → «Получил оплату».
- Курьер (фаза 2): берёт доставку, отмечает забор/доставку.
- Админ: `/admin` — статистика, баны/разбаны, помощь в спорах.

Баны 4 уровней: предупреждение → 10 суток → 30 суток → навсегда (§5.4 ТЗ).
Все таймауты — в `.env` (§11 ТЗ).
